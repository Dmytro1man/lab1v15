**Варіант:** 15 — сутність `Student` (FirstName, LastName, EnrollmentDate)
**Тема:** Узагальнені типи (Generics). `IRepository<T>` з `where`-обмеженнями та тестами.

 Структура

- **IEntity** — інтерфейс з властивістю `int Id { get; set; }`.
- **Student : IEntity** — сутність: `Id`, `FirstName`, `LastName`, `EnrollmentDate`.
- **IRepository<T> where T : IEntity** — методи `GetById`, `GetAll`, `Add`, `Update`, `Delete`.
- **InMemoryRepository<T> where T : IEntity** — зберігає елементи в `List<T>`:
  - `Add` — якщо `Id == 0`, призначає наступний вільний; дубльований `Id` викликає `ArgumentException`;
  - `GetById` — повертає `null` для неіснуючого `Id`;
  - `GetAll` — повертає копію списку;
  - `Update` / `Delete` — для неіснуючого `Id` викидають `KeyNotFoundException`.
- **lab12v15.Tests** — xUnit-тести для всіх п'яти методів, включно з неіснуючими елементами.

 Запуск


dotnet run --project lab12v15
dotnet test


 Відповіді на контрольні запитання

**1. Яка роль where-обмежень у Generics? Приклади.**
Вони обмежують, які типи можна підставити замість `T`, і дозволяють у коді використовувати можливості цього типу. Приклади: `where T : IEntity` (у репозиторії можна звертатися до `item.Id`), `where T : class` (лише посилальні типи), `where T : new()` (тип має публічний конструктор без параметрів).

**2. Навіщо потрібен шаблон IRepository? Які переваги?**
Він відокремлює логіку доступу до даних від решти програми. Можна замінити сховище (пам'ять, база даних, файл), не змінюючи код, що ним користується, а для тестів використовувати `InMemoryRepository`. Також уся робота з даними зосереджена в одному місці.

**3. Чому юніт-тести важливі при розробці узагальнених компонентів?**
Узагальнений код працює з багатьма типами, і помилка в ньому вплине на всі з них. Тести автоматично перевіряють поведінку (зокрема граничні випадки: порожній репозиторій, неіснуючий Id), а після змін швидко показують, що нічого не зламалося.

**4. Які проблеми вирішують Generics порівняно з object?**
Безпека типів (помилки видно під час компіляції, а не виконання), відсутність приведення типів (`cast`) та boxing/unboxing для значущих типів (вища продуктивність), а також чіткіший код без постійних перетворень.
